# A clinical prediction model for problematic levodopa-induced dyskinesia

Analysis code and results for a prognostic model of problematic levodopa-induced
dyskinesia in Parkinson's disease, developed in the Parkinson's Progression Markers
Initiative (PPMI) and reported following TRIPOD+AI. Manuscript in preparation.

The model predicts the absolute probability of problematic dyskinesia, defined as a score
of 2 or more on MDS-UPDRS item 4.1 or item 4.2, at 3, 5, 7 and 10 years from the day
levodopa is started. It uses six variables that are already in the notes of a routine
consultation: age at motor onset, sex, body-mass index, the total MDS-UPDRS, the
tremor-dominant to postural-instability ratio, and freezing of gait.

Development sample: 813 participants, 165 of whom reached the outcome. Optimism-corrected
concordance 0.70; out-of-fold concordance 0.696.

## Why this repository exists

Every number in the manuscript and in the supplement is produced by a script here, and the
scripts are written to be checked rather than believed. Several of them reproduce a stored
result and stop with an error if it no longer matches: `03b_candidate_matrix.py` checks all
39 columns of the analysis matrix, `00b_curated_cache.py` checks all 181 columns of the
curated cut, `04b_table1.py` prints each cell of Table 1 beside the published one, and
`52_multimodal_screen.py` prints the recovered sample and estimate for each of the 89
screened candidates beside the published ones.

Where a published number could not be reproduced, the script says so rather than quietly
replacing it. There are two such cases and both are documented in `02_Codigo/README.md`.

## Layout

| Folder | Contents |
| --- | --- |
| `02_Codigo/pipeline/` | 40 numbered Python scripts and the shared module `cohort.py`, run in the order given in `02_Codigo/README.md` |
| `02_Codigo/pipeline/figuras_R/` | The four R scripts that draw the figures |
| `02_Codigo/pipeline/legacy/` | Nine superseded scripts, kept for traceability. Nothing in the paper comes from them |
| `02_Codigo/exploratory/` | The model-selection history that preceded the six-variable specification. These do not reproduce the manuscript |
| `03_Resultados/` | The tables and figures the scripts produce |
| `05_Calculadora/` | The risk calculator and the frozen model artefacts it deploys |

Start with `02_Codigo/README.md`, which lists what each script produces, and with
`02_Codigo/pipeline/cohort.py`, which is the single definition of the cohort, the six
predictors, the 18-variable candidate pool, the drug-name searches and the
cross-validation protocol.

## Data availability

**The data are not in this repository and cannot be redistributed.** PPMI is
controlled-access. Data are obtained from the PPMI database at
[ppmi-info.org/access-data-specimens/download-data](https://www.ppmi-info.org/access-data-specimens/download-data),
which requires a data use agreement. The scripts read the raw download from a directory
outside this repository, located by two environment variables described below.

Five derived tables carry one row per participant and are excluded by `.gitignore` for the
same reason: `tab27_treatments_per_patient.csv`, `tab31_masking_candidates.csv`,
`tab32_out_of_fold_linear_predictor.csv`, `tab37_excluded_participants.csv` and
`tab51_anchoring_measurements.csv`. Each is regenerated by the script that produced it, so
a reader with PPMI access can rebuild them and every result that depends on them.

## Running the pipeline

Python 3.12.10, with the pinned versions in `02_Codigo/requirements.txt`. The analyses were
originally run on 3.10.12 and reproduce exactly on 3.12.10. The figure scripts need R 4.5
or later.

```bash
export LID_PROJECT_ROOT="/path/to/the/folder/holding/01_Dados_Brutos"
export LID_PROC_DIR="/path/to/04_Dados_processados"
export PYTHONPATH="/path/to/02_Codigo:/path/to/02_Codigo/pipeline"
cd 02_Codigo/pipeline
python 32_internal_performance.py
```

Random seeds are fixed for every bootstrap and cross-validation, so results reproduce on
re-running. One estimator needed work to make that true: lifelines breaks tied event times
in the Aalen-Johansen estimator with unseeded noise, so `12_competing_risk.py` averages the
competing-risk adjustment over 400 seeded tie-breaks and reports their spread.
